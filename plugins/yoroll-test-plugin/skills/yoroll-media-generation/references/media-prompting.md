# 生图 / 生视频提示词方法论

> 来源：提炼自 LGPlatform 的 5 个生产级 system prompt ——
> 《角色图片提示词生成 Agent》《分镜图片和视频提示词生成 Agent》《立绘改写三视图 Agent》
> 《UI提示词生成Agent》《发布封面自动生成Agent》。
> 目的：让插件在用户随口一句"来张仙侠立绘"时，能靠这套方法论把模糊需求加工成
> 结构化、可执行、风格可控的高质量提示词，再调用生成工具。

## 一、好的图片提示词：结构要素

五个 Agent 虽然产出场景不同（角色立绘、分镜画面、三视图、UI、商店封面），但都不允许输出"一整段混合描述"，而是要求**结构化、可视化、可执行**。反推出的通用骨架如下：

1. **主体先行**：第一句必须明确"这是谁/是什么"——核心身份、物种或形态、性别、年龄段。例如"人类女性，年轻，见习女侦探"。主体句要能让模型在读到后续细节前先建立一个清晰锚点。
2. **外观分项描述**：头部特征、五官、皮肤/材质、身材比例、服装。要求"具体、可视化、直接"，明确排斥抽象词（如只写"冷酷""神秘""优雅"），必须转化为可见状态，例如"身体略微前倾，抬头直视前方，下颌收紧"。
3. **外在状态而非心理描述**：情绪、气质一律要落到看得见的姿态、表情、肌肉张力上，不写"不可见的心理活动"。
4. **构图与景别**：单人/单一主体、全身或指定景别、机位角度（低机位仰拍、过肩、俯视等），明确排除不需要的构图（如立绘场景明确排斥半身、近景、特写、多人）。
5. **镜头/景深感**：焦段感（50mm 标准、85mm 人像浅景深、24mm 广角）+ 前后景虚实关系，用于图片的"专业感"，而非堆砌质量词。
6. **场景与背景**：干净简洁、无叙事性杂乱元素；封面类则需明确场景与题材、核心冲突绑定。
7. **光线**：光源位置 + 光质（硬/软）+ 色温 + 阴影处理，强调"方向、质感、色温"三要素而非"氛围形容词"。
8. **风格是独立层，不与主体描述混写**：角色立绘 Agent 明确要求"不要描述视觉风格（二次元、写实、3D、插画风、油画风、赛博朋克美术风格等）"，理由是**风格会在下游与外部视觉风格描述拼接**。这是一个重要的架构启示：主体/场景结构化描述与风格关键词应该分层生成、最后拼接，而不是从一开始就混在一起写，这样风格可以被整体替换而不用重写主体描述。
9. **要求排除（负面清单）**：每条提示词末尾都应显式声明不希望出现的内容，而不是依赖模型"自觉"。
10. **质量词态度**：明确反对空泛质量词堆砌（cinematic / highly detailed / masterpiece / realistic），也反对直接标注画风类型词。用可执行的技术参数（焦段、光线方向、色温、景深、空间关系）替代抽象形容词，这是贯穿所有 Agent 的核心原则。

## 二、视频提示词 与 图片提示词 的差异

图片提示词捕捉"单一决定性瞬间"，像电影海报帧；视频提示词是"导演给摄影师和表演团队的镜头执行简报"，每一行都必须是可直接执行的指令，不是文学描写。差异集中在：

- **运镜（图片没有，视频必须有）**：需要具体运镜方式——dolly 推进、pan 横移、tilt 俯仰、tracking 跟拍、handheld 手持、crane 升降、zoom、rack focus、static 固定。不写则默认 static。可选补充剪辑节奏建议（快切、长镜头、跳切），但须服务于叙事，不能为炫技而炫技。
- **动作要拆解为可执行 beats**：视频提示词必须把动作拆解成 2-4 个按时间顺序排列的节拍（beats），而不是一句笼统的动作描述；图片提示词只需定格一个瞬间的姿态/表情/张力。
- **声音设计是视频独有的必选项**：需要分层次描述——环境底噪（持续）+ 关键音效（时机明确）+ 台词（逐字引用，不改写不总结，标注说话人全称与音色）+ 音色（可感知的声音特征，如"低沉克制""急促发颤""清冷平稳"）。声音描述必须贯穿整个镜头，克制、稳定，不罗列碎片音效。
- **角色身份锚定要在动作之前重复一次**：视频镜头因为要连续播放、可能跨多个 shot，必须先锁定面部、发型、服装、体态等关键特征，再写站位和屏幕方向，最后才写动作节拍，防止 AI 在时间维度上发生角色"漂移"。
- **结尾固定语**：中文视频提示词最后一行固定写"不加字幕"，英文固定写"Don't generate subtitles"，图片提示词没有这个要求。
- **时长/节奏隐含在运镜和剪辑建议中**：该体系不显式声明镜头时长数字，而是通过"景别调度""运镜方式""剪辑节奏建议"间接控制视频的时间感——这提示插件在缺少时长参数时，可以用运镜复杂度和 beats 数量来隐式估计合理时长，而不必强行要求用户提供秒数。

## 三、角色一致性技巧（多张图/多镜头同一角色怎么保持）

这是分镜 Agent 体系设计最精细的部分，核心原则是"身份特征前置锁定 + 显式继承规则"：

1. **每次出现角色都要前置锁定四要素**：面部（年龄感、轮廓、肤色、关键五官）、发型（发色、长短、细节）、服装（颜色、款式、材质、标志性细节如破损/图案/配饰）、体态（高矮、体型、姿态习惯）。锁定完成后才描述动作与情绪，顺序不能反。
2. **禁止用抽象代号指代角色**：不使用 c1/c2 这类内部编号做提示词内的主语，必须用角色姓名或稳定外观标签，因为编号对生成模型没有语义，容易被忽略或误解为文字水印。
3. **连续性分级管理（必须继承 vs 允许变化）**：
   - 必须严格继承：角色外形、场景关键布景/道具/主光方向/色温/空间关系、屏幕方向（人物左右关系、视线方向、进出画方向不能突然对调）、已建立的关键物件与布景状态（门开/关、灯亮/暗、天气等）。
   - 允许自然变化：表情与情绪、细微肢体状态、景别与机位的合理调度、同光源体系下的光比变化。
   这个分级是关键方法论：不是所有东西都要锁死，过度锁死会让画面呆板，只锁"识别性"要素，放开"表现力"要素。
4. **上一轮结果作为连续性参考，但不能覆盖当前事实**：previous_prompt_shots 仅用于外形、方向、布景、光线体系等视觉连续性对齐，不得以"保持连续"为由覆盖本轮剧本中的明确事实——即连续性服务于叙事真实，而非反过来。
5. **三视图复用同一份立绘描述**：立绘改写三视图 Agent 的核心手法是"不改写、不弱化立绘中已经明确的外观、服饰、气质，只转写表达方式"，在 sheet_prompt 中显式声明"三视图中的角色造型、服装、发型、体型、气质与立绘完全保持一致，不随意新增完全不同的服饰或夸张设定"。这说明保持角色一致性最可靠的方法不是重新描述一遍角色，而是**把已确认的 portrait_prompt 原文作为约束条件传给下一步生成任务**，并显式要求"与之保持一致"。
6. **世界观层面的统一性**：角色图片提示词 Agent 要求"同一故事内多个角色要处于同一个世界观和设定体系下，不能让不同角色的设定语言互相冲突"——这是角色间的横向一致性，不只是同一角色的纵向一致性。

## 四、常见风格库 / 风格关键词（从文件中收集）

- **摄影/胶片感基调**：35mm 胶片颗粒感、冷蓝数字影像感、手持纪录质感、Roger Deakins 式侧逆光（用具体摄影师/器材参照代替泛称风格词）。
- **光线哲学关键词**：单点强侧光、自然散射光、夜景低调照明（low-key）、明亮均匀清晰可见光、冷光/暖光/柔和光。
- **景别与镜头关键词**：低机位仰拍、过肩镜头、俯视、50mm 标准、85mm 人像浅景深、24mm 广角。
- **美术/设计风格关键词**：新中式美学、现代简洁风格（UI 场景常用）。
- **构图/画布规格关键词**：16:9 横版、3:4 竖版商店封面、16:9 横版三视图设定图。
- **封面场景专用限定词**：game store cover art（必须显式声明这是商店封面图，而非 logo / poster mockup / UI screenshot / package design / marketing layout）。
- **被排斥但值得记录的风格词**（说明它们通常应作为独立"风格层"关键词使用，而不是写进主体描述）：二次元、写实、电影感、3D、插画风、油画风、赛博朋克美术风格。这些词本身没有错，只是不应该和角色主体描述混在同一段里，应作为可替换的风格层单独拼接。

## 五、负面清单（各 Agent 明确避免的写法）

- **角色立绘**：禁止"角色立绘/人物立绘/设定图"等总标题式开头；禁止半身、近景、特写；禁止坐姿、躺姿、蹲姿；禁止跑动、跳跃、翻滚、攻击、防御、战斗姿势；禁止手持道具、骑乘物、漂浮载具；禁止出现其他人物；禁止复杂场景/复杂背景叙事；禁止抽象比喻、文学化修辞；禁止文本、字幕、标志、logo、水印；禁止血腥暴力、色情、仇恨、违规内容。
- **分镜图片/视频**：禁止拼贴感、多时间点混合、叙述性描述、分屏视角；禁止堆砌空泛质量词（cinematic / highly detailed / masterpiece / realistic）；禁止直接标注画风类型（写实、动漫、3D 等）；禁止用"保持连续"为由篡改本轮剧本事实；禁止虚构关键剧情事件或台词；禁止强化血腥、色情、仇恨、违法内容（用压迫感构图/表情张力/动作结果/环境状态变化替代直白展示）。
- **三视图**：禁止随意新增与立绘不同的服饰或夸张设定；禁止夸张透视；禁止动态/剧烈姿势；禁止出现其他角色或复杂场景。
- **UI 提示词**：禁止 UI 遮挡游戏核心画面，UI 占屏比例不超过 10%；禁止用数值堆砌代替文本信息展示（尽量用文本，减少数字直接暴露）。
- **发布封面**：禁止出现 Logo、游戏标题、文字、字母排版、水印、字幕、平台 UI、按钮、徽章、边框、海报 Mockup 或包装展示，且要求正向描述之外必须显式写出负向限制句（no logo, no game title, no text, no typography, no watermark, no subtitle, no UI, no border）——即"仅靠正向描述规避"是不够的，必须显式补一句负面声明。

## 六、给插件独立生成能力的落地建议

1. **两段式生成**：先生成"主体+场景+构图+光影"结构化描述（中性、不含风格词），再从风格库中选取/拼接风格关键词层，二者拼接成最终提示词。这样"来张仙侠立绘"这类请求可以先按角色结构骨架生成主体描述，再套用"仙侠"对应的风格关键词（如水墨渲染、飘逸衣袂、仙气雾感等，需按此方法论从用户已有风格库或对话上下文中提取，不要凭空堆砌质量词）。
2. **图片请求必须补全负面清单**：即使用户没说，也要按场景类型（角色/分镜/UI/封面）自动附加对应负面清单。
3. **视频请求在图片结构基础上叠加运镜、beats、声音设计、结尾固定语**四个模块，不要另起一套体系。
4. **多图/多镜头请求要显式传递已确认的角色描述原文**作为一致性约束，而不是让模型凭记忆复现角色。
5. **语言跟随用户输入语言**：中文输入出中文提示词，英文输入出英文，其他语言默认英文（发布封面场景要求提示词本身用英文书写，即使输入是其他语言，属于该场景的特例，需按生成目标模型的语言习惯决定，不可一概而论）。
