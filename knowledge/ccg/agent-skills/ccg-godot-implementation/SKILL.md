# Implement a CCG Godot Game

1. Read `CCG.md`, `CCG_AGENT_GUIDE.md`, and existing design files. Treat tool-returned project and scene paths as authoritative.
2. Inspect with `godot_scan_project` and `godot_read_scene` only as needed. Prefer `godot_create_scene`, `godot_patch_scene`, and `godot_attach_script` over rewriting scene files.
3. Preserve template gameplay systems and helper scripts unless the task specifically requires changing them. Make the smallest coherent scene and script changes.
4. In `.tscn`, declare external resources at the top and reference them with `ExtResource`. Never use `load()` or `preload()` in scene data.
5. **Player-visible art (hard gate):** every character the player controls or fights (hero, enemies, bosses, NPCs) and every key interactive item (main collectibles, quest/puzzle objects) must use real generated or library art — plain `ColorRect`/`CSGBox`/primitive-mesh placeholders are not an acceptable final state for these, regardless of how simple the game is. Generic set dressing (ground tiles, background layers, filler decoration) may stay procedural when it doesn't carry gameplay identity.
   - check `use_asset_library` first (query in English, by theme) for anything generic — props, environment pieces, common creatures, UI icons. Library hits are free and instant, so this always runs before any generation call; only generate new content when the library has no reasonable match, or for something title-specific (hero/boss/key art).
   - **3D characters/props:** create a concept image with `generate_concept_image` when visual identity matters, then `generate_3d_asset` (Tripo) with the required rig and animation options, then pass the exact returned local path/URL to `import_asset_to_godot` (or `generate_3d_model` for a non-Tripo provider) — verify scale, orientation, collisions, animation state changes, and scene references after import.
   - **2D sprite-based characters/props** (the game uses `Sprite2D`/`AnimatedSprite2D`, not 3D meshes): use `generate_sprite_sheet` (first generate a reference image with `generate_concept_image` and pass it as `reference` for cross-frame consistency), then wire the returned `path`/`frames`/`frameWidth`/`frameHeight` into a `SpriteFrames` resource on an `AnimatedSprite2D` (or `Sprite2D.hframes`/`vframes` for a simple grid) — always use the returned path and dimensions verbatim, never assume `.png` or a hardcoded frame size. If `frameQuality` comes back `"suspect"`, fall back to a single static image on a tween instead of an inconsistent/broken animation.
   - Before calling this step done, list every player-visible character/key item and its art source (library hit / generated / — none —); any "— none —" against something in scope for this gate is a blocker, not a stylistic choice.
6. **UI chrome:** before hand-building any Button/Panel/ProgressBar styling, call `select_ui_kit` once per game (describe genre/theme/style; it scores and records a curated kit from a library of 10) then `materialize_ui_kit`, which copies the kit's art into `assets/ui/<kitId>/` and generates `assets/ui/<kitId>/theme.tres` — a ready-to-use Godot `Theme` resource wiring whichever of these the kit provides: `Button`/`Panel`/`PanelContainer`/`ProgressBar`/`TabBar`/`LineEdit`/`HSlider`/`PopupPanel` styles, `SecondaryButton`/`DangerButton`/`ErrorLineEdit` type variations, `CheckBox` checked/unchecked/radio icons, an `HSlider` grabber icon, and a themed `default_font` (already chained to the CJK fallback font, so you don't need to touch fonts separately). Set the returned `theme_res_path` on your scene's root `Control` node's `theme` property (or Project Settings → GUI → Theme → Custom Theme for a project-wide default) to skin every control — and its text — at once; set a node's `theme_type_variation` to `SecondaryButton`/`DangerButton`/`ErrorLineEdit` for those skins. Do not hand-roll flat `StyleBoxFlat` chrome or reassign the project default font back onto individual controls once a kit is materialized — that produces the plain/ugly UI this step exists to avoid. When building a HUD/menu box in code, `PanelContainer` (auto-sizes to its children, so it's the usual choice for a HUD box wrapping a `VBoxContainer`/`HBoxContainer`) and plain `Panel` are both covered by `panel.main` — Godot treats them as separate theme types even though they look alike, so don't assume only one needs checking. Not every component role has a native Godot theme slot (e.g. `switch.*`, `result.victory`/`result.defeat`, `slot.action`, `button.close`/`button.back` have no stretch geometry or built-in control) — the tool's response lists these explicitly and tells you to use the copied texture directly (`TextureButton.texture_normal`/`TextureRect.texture`), not to invent a `StyleBoxFlat` fallback for them.
7. If a media provider fails, retain a working project with an explicit programmatic or template fallback. Do not fabricate asset paths.
8. **CJK text rendering (hard gate):** the project's default UI font (`res://assets/fonts/NotoSansSC.ttf`, set via `project.godot`'s `[gui] theme/custom_font`) has Chinese glyphs; the engine's built-in fallback font does not. This project default only covers `Control` nodes (`Label`, `Button`, `RichTextLabel`, ...) that have no font override. Any time you assign a specific/decorative font to a node or Theme that will display Chinese text (titles, HUD, dialogue, buttons) — including template-provided fonts like `lilita_one_regular.ttf` — you must add `res://assets/fonts/NotoSansSC.ttf` to that font resource's `fallbacks` so missing glyphs render instead of boxes. Prefer leaving Chinese-displaying nodes on the unmodified project default font when a decorative font isn't required. `Label3D`/`draw_string()`/world-space text do not inherit the project default at all — they need an explicit font (with the CJK fallback) assigned. Verify by reading the actual rendered web preview screenshot for any Chinese text, not by only checking the font config exists.
9. Run `godot_preflight_check` after structural changes, then `godot_run_playtest` and the required web preview or export. Repair failures before finishing.
